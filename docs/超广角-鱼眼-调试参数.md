# 超广角（鱼眼）摄像头调试参数

> 对象：鱼眼那颗（DECXIN CAMERA，`1bcf:2cd1`，USB 端口 `10.4`）
> 绑定路径：`/dev/v4l/by-path/pci-0000:00:14.0-usb-0:10.4:1.0-video-index0`
> 本文所有数值均为 **2026-11-02 本机实测**，未实车验证。
> 配套工具：[wide-cam-ctl.py](../launch/wide-cam-ctl.py)

## 零、前提：两颗摄像头是**同一个模块，只有镜头不同**

实测确认（这决定了下面哪些参数能共用、哪些不能）：

| 层面 | 是否相同 | 证据 |
| --- | --- | --- |
| VID/PID | ✅ 相同 | 都是 `1bcf:2cd1` |
| USB 序列号 | ✅ 相同 | 都是 `01.00.00` → `/dev/v4l/by-id` 里只有**一条** DECXIN 链接 |
| 支持格式/分辨率 | ✅ 相同 | 都到 4K，MJPEG + YUYV，档位一模一样 |
| UVC 控制项 | ✅ 相同 | 都是那 11 项，范围/默认值一字不差 |
| 传感器/ISP | ✅ 相同 | 同型号模块 |
| **镜头** | ❌ 不同 | 一颗普通视角，一颗圆形像场鱼眼 |

### 这意味着

| 项目 | 结论 |
| --- | --- |
| UVC **范围**（min/max/默认） | 两路通用，照第三节的表用就行 |
| UVC **建议值** | **要分开调**。镜头不同 → 暗角、通光量、边缘锐度都不同；鱼眼边缘衰减更严重，通常需要更高的 contrast/sharpness、更低一点的 gain |
| **几何内参（f、畸变、像场、主点）** | **完全不能共用**，只由镜头决定 |
| 设备编号 | 描述符层面**无法区分**。只能靠 USB 端口路径（见下） |

### ⚠️ 唯一可靠的区分方式：USB 端口

```
端口 10.3 → 普通视角 → 路面  ROAD_CAM=/dev/v4l/by-path/pci-0000:00:14.0-usb-0:10.3:1.0-video-index0
端口 10.4 → 鱼眼     → 广角  WIDE_CAM=/dev/v4l/by-path/pci-0000:00:14.0-usb-0:10.4:1.0-video-index0
```

- ❌ **不要用 `/dev/v4l/by-id`**：序列号撞车，只有一条链接且指向"后插入的那颗"，用它等于随机
- ❌ **不要用 `/dev/videoN`**：重插/重启会漂
- ⚠️ 换 USB 口后 by-path 会变；把两颗摄像头物理对调，路面/广角会**静默对调**，软件发现不了

## 一、先认识到它是什么样的"超广角"

它不是普通宽视角镜头，是一颗**圆形像场的鱼眼**，而且**画面被 16:9 传感器裁掉了上下**：

| 项目 | 1280×720 | 1920×1080 |
| --- | --- | --- |
| 像场（镜头成像圆）直径 | **≈1024 px** | **≈1537 px**（1.5× 一致） |
| 左右黑边 | 左 148 / 右 108 px | 左 222 / 右 161 px |
| 像场占画面宽 | 80% | 80% |
| 水平视场（按 180° 对角线假设） | **≈180°** | ≈180° |
| 垂直视场 | **≈127°** | ≈127° |
| 画面四角 | 全黑（在像场圆外） | 全黑 |

**关键结论：水平能用满 180°，但垂直方向被裁掉约 1/3，四角永远是黑的。**
这是镜头+传感器尺寸不匹配导致的，软件改不了，只能靠去畸变后裁切中心区使用。

## 二、几何内参（OP 需要的那几个数）

### 2.1 现状：**OP 现在给广角的内参是错的**

`common/transformations/camera.py:68`：PC 模式统一走 `_ar_ox_config`，其中

```python
_ar_ox_fisheye = CameraConfig(1928, 1208, 567.0)   # 这是 comma 设备内视摄像头
("pc", "unknown"): _ar_ox_config                    # ← 我们的广角也吃这个
```

也就是说 OP 认为广角是 **1928×1208、f=567**，而实际是 **1280×720、f≈326**。
主点也从 (964, 604) 变成 (640, 360)。这个不匹配会让 `get_warp_matrix()` 生成的单应矩阵完全偏掉。

### 2.2 实测候选值（等距鱼眼模型 `r = f·θ`）

以像场水平半径 `r` 反推，三种 FOV 假设对应三个焦距：

| 假设镜头水平 FOV | 1080p 焦距 | **720p 焦距** | 归一化 f/W |
| --- | --- | --- | --- |
| 160° | 550 px | **367 px** | 0.2865 |
| 170° | 518 px | **345 px** | 0.2696 |
| **180°（推荐起点）** | 489 px | **326 px** | 0.2546 |
| 190° | 464 px | **309 px** | 0.2412 |

> 归一化 `f/W` 在两档分辨率下一致（0.2546 / 0.2548），说明这个比例是镜头固有的，可以放心按分辨率缩放。

**建议起点（1280×720）：`f = 326.0`**
（不确定度 ±10%，最终必须靠棋盘格标定定死）

### 2.3 主点

| 项目 | 值 | 说明 |
| --- | --- | --- |
| cx | **≈660**（画面中心 640，偏右 +20） | 左右黑边不对称 148 vs 108，确实偏了 |
| cy | **暂取 360**（画面中心） | 垂直方向被场景明暗干扰，测不准；四角黑角说明像场圆中心应当接近画面中心 |

⚠️ 现在 `CameraConfig` **只支持主点在正中心**（`width/2, height/2`），要用上面这个 cx 就得给 `CameraConfig` 加 `cx/cy` 字段——这是下一步的代码改动。

## 三、硬件 UVC 参数（可以现在就调）

两颗 DECXIN 控制项完全一样。范围是设备报告的真实范围。

| 参数 | CID | 范围 | 默认 | **广角建议** | 说明 |
| --- | --- | --- | --- | --- | --- |
| brightness | `0x980900` | -64..64 | 0 | **0** | 整体偏暗/偏亮先动这个 |
| contrast | `0x980901` | 0..95 | 0 | **20**（15~30） | 默认 0 非常平，鱼眼更糊 |
| saturation | `0x980902` | 0..255 | 70 | **80** | 太高路面颜色失真 |
| hue | `0x980903` | -2000..2000 | 0 | **0** | 一般不动 |
| white_balance_auto | `0x98090c` | 0..1 | 1 | **1** | 要固定色温才设 0 |
| gamma | `0x980910` | 64..300 | 100 | **100**（暗部差提到 130~160） | |
| gain | `0x980913` | 0..255 | 100 | **90** | 过曝往下压 |
| power_line_frequency | `0x980918` | 0..2 | 1 | **1 = 50Hz** | 中国大陆，设错室内闪 |
| white_balance_temp | `0x98091a` | 2800..6500 | 4600 | **4600** | 仅自动白平衡关闭时生效 |
| sharpness | `0x98091b` | 0..7 | 0 | **3**（2~4） | 默认 0 很软，鱼眼边缘更明显 |
| backlight_comp | `0x98091c` | 16..160 | 64 | **48** | 下行强逆光时压低可减过曝 |

### camera class 控制项（`0x009a09xx`）——**存在但基本是坑**

这 6 项是早先漏掉的（暴力扫 ID 时上界卡在 `0x009A0000`，而它们正好在 `0x009A09xx`）。
现在 `--show` 用「NEXT_CTRL 走一遍 + 已知区间显式补扫」的混合枚举，能完整显示 **19 项**。

| 参数 | CID | 范围 | 当前 | 实际效果 |
| --- | --- | --- | --- | --- |
| exposure_auto | `0x009a0901` | 0..3 菜单 | **3 = APERTURE_PRIORITY** | 只有 1/3 能设，见下 |
| exposure_absolute | `0x009a0902` | 1..10000 | 156 | 仅 MANUAL 模式生效（平时 INACTIVE） |
| focus_absolute | `0x009a090a` | 0..1023 | 334 / 573 | **无效**，见下 |
| focus_auto | `0x009a090c` | 0..1 | 1（开） | **无效** |
| pan / tilt / zoom | `0x009a0908` / `0909` / `090d` | — | 0 | 无效（固定镜头） |

#### ❌ 对焦控制是假的（实测）

手动扫遍 `focus_absolute` 全范围 **0 → 1023**，画面清晰度（拉普拉斯方差）只变化 **1.0 倍**：

```
Focus=0 清晰度 3932    Focus=500 清晰度 3896    Focus=1023 清晰度 3895
```

→ 这颗是**固定焦距镜头**，UVC 只是把控制项报了出来，`focus_auto=1` 空转。
**对焦只能拧镜头**——早先"只能拧镜头"的判断在实践上对，但"设备没这个控制项"的说法是错的。

#### ⚠️ 曝光模式：只有两个能设

| 设置目标 | 结果 |
| --- | --- |
| 0 = AUTO | ❌ `EINVAL` 写不进去 |
| 1 = MANUAL | ✅ 可设 |
| 2 = SHUTTER_PRIORITY | ❌ `EINVAL` |
| 3 = APERTURE_PRIORITY | ✅ 可设（当前值） |

实测四种模式下过曝像素占比都是 2~2.6%、平均亮度 52 —— **现在曝光本来是正常的**。
之前看到的"过曝白团"是场景问题（对着室内强光窗），不是参数设错。

真要锁死曝光（夜间防自动曝光来回抽动）：`exposure_auto=1`(MANUAL) + 调
`exposure_absolute`（1..10000，越小越暗）。

### 用法

两套预设都内置了（同一模块，UVC 范围共用；建议值按镜头分开）：

- `--preset wide`（默认）：上表这一套，用于鱼眼
- `--preset road`：`contrast=15 / saturation=75 / gain=95 / sharpness=2 / backlight_comp=56`，用于普通视角那颗

```bash
cd ~/openpilot
./launch/wide-cam-ctl.py --show                              # 读 /dev/video4 全部值
./launch/wide-cam-ctl.py --preset wide                       # 鱼眼预设
./launch/wide-cam-ctl.py --device /dev/video2 --preset road  # 普通视角预设
./launch/wide-cam-ctl.py --set gain=80 sharpness=4           # 临时改单项
./launch/wide-cam-ctl.py --device /dev/video2 --show         # 看路面那颗
```

> 也可以把 `--device` 给成 by-path：
> `--device /dev/v4l/by-path/pci-0000:00:14.0-usb-0:10.4:1.0-video-index0`

⚠️ 三个限制：
1. **有人开流时报 EBUSY** —— 先关 guvcview / 别让 op 在跑
2. **重插/重启后回到默认** —— UVC 控制项不持久化
3. 想固化有两条路：(a) 在 `run-songpro23.sh` 里 source 完 env 后调一次 `--preset`；(b) 写 udev rule（要动 `/etc`，按工作区纪律得先确认）

## 四、鱼眼畸变：为什么必须去畸变

`common/transformations/model.py:65` 的 `get_warp_matrix()` 是**纯针孔单应**：

```python
camera_from_calib = intrinsics @ view_frame_from_device_frame @ device_from_calib
warp_matrix = camera_from_calib @ calib_from_model     # 3×3，没有任何畸变项
```

`bigmodel_frame` 那个 bool 只是选模型内参，**不是**畸变模型。所以：

> 把未去畸变的鱼眼图直接喂进 `wideRoadCameraState`，模型看到的是被严重弯曲的世界 —— 车道线在边缘会弯、近处物体尺度错乱。这颗镜头 180° 视场，边缘畸变极大，不能当"宽一点的针孔"用。

正确做法：**在 camerad 里先 `cv2.fisheye.undistortImage` / `remap` 去掉畸变，再转 NV12 送去 vipc**。

### 4.1 标定步骤（产出 K 和 D）

1. 打一张棋盘格（建议 9×6 内角点，方格 25 mm），贴在硬板上保持平整
2. 用 `guvcview -d /dev/video4 -x 1280x720 -f MJPG` 实时预览，**不同角度/距离拍 20~30 张**，覆盖：画面四角、正对、倾斜 30~45°、远近
3. 标定脚本骨架：

```python
import cv2, numpy as np, glob
PATTERN = (9, 6)          # 内角点数，按你的板子改
SQUARE  = 0.025           # 方格边长（米）
objp = np.zeros((PATTERN[0]*PATTERN[1], 3), np.float32)
objp[:, :2] = np.mgrid[0:PATTERN[0], 0:PATTERN[1]].T.reshape(-1, 2) * SQUARE
obj, img = [], []
for f in sorted(glob.glob("/tmp/calib/*.jpg")):
    g = cv2.cvtColor(cv2.imread(f), cv2.COLOR_BGR2GRAY)
    ok, c = cv2.findChessboardCorners(g, PATTERN, None)
    if ok:
        obj.append(objp); img.append(cv2.cornerSubPix(g, c, (11,11), (-1,-1),
            (cv2.TERM_CRITERIA_EPS+cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001)))
K = np.zeros((3,3)); D = np.zeros((4,1))
size = (1280, 720)
flag = cv2.fisheye.CALIB_RECOMPUTE_EXTRINSIC | cv2.fisheye.CALIB_FIX_SKEW
rms, K, D, _, _ = cv2.fisheye.calibrate(obj, img, size, K, D, flags=flag,
    criteria=(cv2.TERM_CRITERIA_EPS+cv2.TERM_CRITERIA_MAX_ITER, 100, 1e-6))
print("RMS", rms); print("K =", K.tolist()); print("D =", D.ravel().tolist())
```

4. 产出形如（**下面是占位值，必须用实测替换**）：

```
K = [[326.5,   0.0, 660.0],
     [  0.0, 326.0, 360.0],
     [  0.0,   0.0,   1.0]]
D = [-0.0321, 0.0087, -0.0021, 0.0004]   # k1, k2, k3, k4
RMS < 0.5 px 才算合格；> 1 px 说明拍摄覆盖不够或板子不平
```

### 4.2 去畸变之后再裁切

去畸变后四角会变成黑区/拉伸区，必须裁掉。裁切比例按去畸变后的 P 矩阵定，建议保留画面中心 **85%** 左右。

| 项 | 状态 |

| 鱼眼去畸变 | ❌ 未实现，当前鱼眼图是原样送进模型的 |

### 已知偏差（记进 AGENTS §八 备查）

1. `launch/env/songpro23.env` 里的 `WIDE_FOCAL=605.0`、`ROAD_FOCAL=2320.0` 在本分支**都没有消费方**，改它们没有任何效果。真正生效的地方是 `common/transformations/camera.py` 的 `DEVICE_CAMERAS[("pc","unknown")]`。
2. `get_warp_matrix()` 不支持任何畸变模型 —— 鱼眼必须预处理，不能靠加参数解决。
3. **曝光/对焦控制项存在但不等于能用**（11-02 实测订正）：`focus_absolute`/`focus_auto` 是空转（固焦镜头）；`exposure_auto` 只有 MANUAL(1) 和 APERTURE_PRIORITY(3) 能写，AUTO(0) 返回 EINVAL。
4. **两颗摄像头序列号都是 `01.00.00`**，`/dev/v4l/by-id` 里只有一条 DECXIN 链接（指向后插入那颗）。任何"按 by-id 区分两颗"的方案都是错的，只能用 `by-path` 按端口。
5. UVC 控制项**不持久化**：重插/重启回默认值。要在启动时自动应用，需在 `run-songpro23.sh` 里加一步（或写 udev rule，要动 `/etc`）。
6. **摄像头角色识别已自动化**：`CAM_AUTODETECT=1` 时 `camerad` 用画面特征（鱼眼四角死黑）判断哪颗是路面/广角，换 USB 口或物理对调都不用改配置。逻辑在 `cpv8/tools/webcam/camdetect.py`，可单独跑 `-m tools.webcam.camdetect`。
7. **桌面预览器**：`~/Desktop/摄像头预览.desktop` → `launch/preview-cam.py`，可现场选摄像头和预览模式，开预览前自动把 sharpness 归零（退出还原），便于判焦。

## 七、去畸变已实现（2026-11-02）

### 为什么必须做

不是"文档要求"，是**代码结构决定的**。openpilot 广角通路全程针孔模型：

| 位置 | 代码 | 说明 |
| --- | --- | --- |
| `common/transformations/model.py:65` | `get_warp_matrix()` | 只有 `intrinsics @ R @ 外参 @ calib_from_model`，3×3 单应，**无畸变项** |
| `selfdrive/modeld/modeld.py:328` | `model_transform_extra` | 广角流就是用 `dc.ecam.intrinsics` 走上面那个函数 |
| `selfdrive/ui/qt/onroad/annotated_camera.cc:85` | `// TODO: use proper perspective transform?` | UI 自己都标了 TODO |

全仓搜 `undistort` 只有一句注释。官方/第三方文档里**没有明文写"必须去畸变"**，
但把圆形鱼眼图喂进纯针孔变换，几何一定是错的 —— 所以是事实上的必需项。

### 实现

| 文件 | 作用 |
| --- | --- |
| `cpv8/tools/webcam/lens.py` | Kannala-Brandt 模型 + `initUndistortRectifyMap` 预计算 + 逐帧 `remap` |
| `cpv8/tools/webcam/camera.py` | `CameraMJPG` 增加 `lens_file` 参数，在 **BGR 阶段**（转 NV12 之前）去畸变 |
| `cpv8/tools/webcam/camerad.py` | 只对 `wideRoadCameraState` 生效，由 `WIDE_UNDISTORT` / `WIDE_LENS_FILE` 控制 |
| `cpv8/tools/webcam/calib_lens.py` | 棋盘格标定，产出同格式 JSON |
| `launch/env/wide_lens.json` | 当前参数（实测估计：f=326, cx=660, cy=360, D=0） |

`D=[0,0,0,0]` 不是随便填的：Kannala-Brandt 模型在 D 全 0 时正好退化为纯等距
`r = f·θ`，与本机实测假设自洽。

### 实测结果

- 画面：车头盖边缘、杆子、建筑原本弯曲的直线全部变直，无黑角，满帧 1280×720
- 帧率：**无损**。开去畸变后广角仍是 **19.0 fps**（路面 18.9 fps）
- 注意：不能用 `cv2.fisheye.estimateNewCameraMatrixForUndistortRectify`，在近 180°
  鱼眼上它算出退化解（主心变 5.7e16，整帧全黑），所以是手工构造新内参 + `fov_scale`
