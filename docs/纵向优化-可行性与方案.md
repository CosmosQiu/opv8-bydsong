# 纵向优化：现状能力 / 可行方案 / 调试方法（2026-11-01）

> 针对四个症状：**起步迟钝、加塞应对差、急加速、急减速**。
> 结论先行：**这版 OP 对宋 Pro 的纵向目前是「纯透传」——它不计算、不修改加减速指令**。
> 手册 §2.2 里那张 `K_ACCEL_*` 表是**死代码**（全仓无人引用）。要改善，只有"有限干预"和"接管纵向"两条路。

## 2. 四个症状 → 归因 → 能不能改

| 症状 | 根因 | 现在能改吗 | 要改需要什么 |
| --- | --- | --- | --- |
| **起步迟钝**（前车走了它不动） | 原车 stop&go 设计：要么踩油门/按 RES，要么等前车驶离超过阈值 | ❌ | ① op 接管纵向（`autoResumeSng=True`、`startAccel=0.8` 已配好）② 或有限干预：在透传里补 `ResumeFromStandstill` |
| **加塞应对差** | 原车单目+毫米波对切入识别慢；op 侧 `radarUnavailable=True`，没有雷达通道 | ❌ | op 接管纵向 + 视觉 lead（`longitudinal_planner.parse_model`），雷达对宋 Pro 暂不可用 |
| **急加速** | 原车 MPC 的正加速度斜率/峰值大 | ⚠️ 部分 | 限幅透传：压 `AccelCmd` 上限、调 `ComfortBandUpper` / `JerkUpperLimit` |
| **急减速** | 同上，负向 | ⚠️ 部分 | 限幅透传：约束负 `AccelCmd` 下限、软化 `JerkLowerLimit` |

> 「⚠️ 部分」= 可以在不接管纵向的前提下，对**透传的原车指令**做有界裁剪。收益有限（改不了决策，只改执行力度），
> 但风险远低于接管，适合先试水。

## 3. 三条路（按风险从低到高）

### A. 只测不改（0 风险，建议**立刻**做）

现在的痛点是"感觉差但说不清差多少"。先把指标量化，后面所有改动才有意义。
不需要改代码：`ACC_CMD` 帧本身就在 rlog 的 CAN 数据里，离线解析即可。

```bash
# 跑完一段路后，用现有的工具链看信号（需硬件到位）
cd ~/openpilot/cpv8 && source .venv/bin/activate
# PlotJuggler 打开 rlog，或脚本解析：
#   CAN 总线 ESC 上 0xAF 附近的 ACC_CMD：AccelCmd / JerkUpperLimit / JerkLowerLimit / ComfortBand*
#   carState：vEgo / aEgo / standstill
#   radarState.leadOne（此处应恒为 invalid）
```

要定义的 4 个数（建议记进 `docs/调参记录.md`）：

| 指标 | 算法 |
| --- | --- |
| 起步延迟 | 前车 `vLead` 由 0 变为 >0.5 m/s → 自车 `vEgo>0.3 m/s` 的时间差 |
| 加速冲击 | `|d(AccelCmd)/dt|` 峰值 + `AccelCmd` 峰值 |
| 减速冲击 | 同上，取负向 |
| 加塞响应 | 切入目标出现 → 自车开始减速的时延 / 最小 TTC |

### B. 有限干预：给透传值加"有界滤波器"（中风险）

在 `bydcan.acc_cmd()` 的 `not longActive` 分支里，对复制出来的 `values` 做**上下限与斜率限制**，
再打包。要点：

```python
# 伪代码：只在 longActive=False 时生效，且全部有界
v = float(values["AccelCmd"])
v = np.clip(v, -2.0, 0.9)                      # 硬限：不大脚油门/不急刹
v = last_v + np.clip(v - last_v, -0.15, 0.15)  # 斜率限：每秒最多 1.5 m/s^2 变化（50Hz×0.03）
values["AccelCmd"] = v
values["JerkUpperLimit"] = min(values["JerkUpperLimit"], 上限)   # 注意原车字段范围未知
values["JerkLowerLimit"] = max(values["JerkLowerLimit"], 下限)
```

风险与纪律：
- 原车 `ACC_CMD` 各字段的**合法范围未知**，越界可能触发 ACC 故障/退出 → 第一版只动 `AccelCmd` 一项，其余不碰。
- 一定加"急刹优先"例外：`AccelCmd < -2` 或 TTC 过小时**不做裁剪**，保命优先。
- Python 改动，不用重编译；`.bak.<日期>` 备份 + 重启 op 即生效/回滚。
- 先在**封闭场地**低速验证，再上人少路段。

这条能改善「急加速/急减速」，**但改善不了起步迟钝和加塞**（那是决策层的事）。

### C. 让 op 接管纵向（高收益，高风险）

一行代码 + 一个参数：

```python
# byd/values.py:158 —— 把宋 Pro 加进 EXP_LONG_CAR（示例，未执行）
EXP_LONG_CAR = {..., CAR.BYD_SONG_PRO_DMI_22, CAR.BYD_SONG_PRO_DMI_23}
```
```python
# 运行时开关（Params）
AlphaLongitudinalEnabled = 1   # card.py:92 读取 → 传给 get_params
```

开启后：`longActive=True` → op 的 planner 出 `AccelCmd` → `bydcan.acc_cmd` 覆盖原车指令。
这时才谈得上：视觉 lead 提前识别加塞、jerk 限制、`MyDrivingMode`(ECO/SAFE) 性格、交通灯停走。

**前提条件（缺一不可）**：
1. **panda 到手**（现在没有 `/dev/ttyACM*`，panda 的 safety 模型要放行 BYD 的 ACC 报文）。
2. `safety_byd.h` 对 `SONG_PLUS_DMI` flag 的纵向权限**要确认**（不是本仓库可改的范围，需看 panda 固件）。
3. 封闭场地验证：起步、跟车、急刹、加塞、坡道、低速蠕行，逐项过。
4. 保留"一键退出"：方向盘按键取消 + 脚刹，随时能回原车。

> ⚠️ 这是把纵向从"原车 ECU"切到"笔记本上的模型"——软件跑在 PC 上，一次卡顿就是一次错失制动。
> 作者把宋 Pro 排除在 `EXP_LONG_CAR` 之外是有道理的，别为了体验先跳这一步。

## 4. 陀螺仪的真正定位（别抱期待）

**它治不了这四个症状里的任何一个。** 数据链路是：

```
IMU ──串口──> sensord ──> gyroscope/accelerometer 服务 ──> locationd（仅此一家）
                                                        └──> livePose.orientationNED
                                                              └──> longitudinal_planner 算 coast accel（仅长控时）
```

- `longitudinal_planner.py:108` 用 `carControl.orientationNED[1]`（pitch）估滑行加速度 —— 这是**唯一的间接联系**，
  而且只有 op 接管纵向后才进这条路径；坡度估计更稳一点，边际收益很小。
- 纵向真正的输入是：`vEgo`/`aEgo`（轮速微分）、`radarState`（宋 Pro 不可用）、模型 lead、`cruiseSpeed`。**没有陀螺仪**。

**那它有什么用？当测量仪器。** 这是"接陀螺后怎么调"的正确答案：

1. **标定 CAN 的 `aEgo`**：IMU 给独立的高频真加速度，与 `carState.aEgo` 做互相关，量出 CAN 的**延迟与量化误差**
   （原车 ACC 的"反应慢"到底慢在传感器、决策还是执行器，这一步能拆开）。
2. **验证 jerk 指标**：B 方案里我们改的是**指令**，IMU 能测**实际**加速度，验证裁剪是否真的落到车上。
3. **坡道补偿**：静止/低速时 IMU 的俯仰角可作为 pitch 的参照，判断 coast accel 估得准不准。

接入注意（会踩的坑）：
- 代码把 source 强行填成 `LSM6DS3TRC`、量程写死 2000dps/16g，模块量程不同会算错；
- 安装角度决定 pitch/roll 的质量，装歪会污染 `calibrationd`（比没有更糟）；
- 静态零偏要先标定，否则 `locationd` 的 EKF 会被拉偏。

## 5. 调试纪律（不管走哪条路都适用）

1. **一次只改一个变量**，改完只跑同一段路（同方向、同时段、相近电量/胎压）。
2. 每次至少 3 个来回，取**中位数**，别用单次"感觉"下结论。
3. 指标先行：先有数字，再谈"平顺了"。
4. 任何代码改动：`.bak.<日期>` + 一行回滚命令，写进 `docs/调参记录.md`。
5. **上车的每一版都必须能在 10 秒内退回原车**（退出 op / 松手 / 脚刹）。

---

## 6. 建议顺序

1. **现在（无硬件）**：把 A 的测量脚本准备好（离线解析 rlog 的 ACC_CMD），列好指标表。
2. **硬件到位**：先跑手册 §3 阶段 0/1/2，确认指纹与横向正常；**纵向先不动**。
3. **基线采集**：跑 3 段固定路线，记录四个指标的原始值。
4. **试 B**：只加 `AccelCmd` 上下限 + 斜率限制，重采同样 3 段，对比。
5. **再决定要不要 C**：只有 B 明显不够、且 panda + safety 都确认了，才动 `EXP_LONG_CAR`。
6. 陀螺仪：等 B/C 稳定后接，先当测量仪器，**不要**一开始就让它进 EKF。
